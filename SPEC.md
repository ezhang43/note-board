# BusyAnts (Note Board) — Build Spec v1

As of 2026-10-02 · Owner: Eric Zhang

## Overview

BusyAnts (built as "Note Board"; the name shows in the browser tab, the installed app and the sign-in screen) is a web-based visual board for notes, checklists and links, in the spirit of Milanote. Version 1 is a single-user app that runs in the browser and saves its boards between visits; a person can have several boards, and boards inside boards. The published site (https://ezhang43.github.io/note-board/) also syncs every board to the signed-in Google account (any Google account), so the same boards open on every device.

The clickable prototype (`note-board-prototype-reference.html`) is the reference for look and behavior. Where this spec and the prototype disagree, this spec wins.

- **Who it's for:** one person organizing ideas, plans and tasks on a free-form canvas.
- **Version 1 goal:** everything in this spec working reliably, saved in the browser and synced to the owner's account.
- **Not in version 1:** image cards. Sharing and real-time collaboration are being built (see "Sharing and editing together").

## Build rules for Claude Code

The owner reads code at a beginner level and will not review it line by line, so every change must be verifiable by tests and by clicking through the app.

1. **Stack:** a web app in TypeScript with React, built with Vite. Claude Code may propose an alternative once, with reasons, before writing code; the choice is then recorded in `CLAUDE.md`.
2. **Saving:** the board saves automatically to the browser (localStorage) after every change and loads on start. The published site also syncs it to Firebase (see "Sign-in, sync and offline"); running the app locally stays browser-only.
3. **One source of truth:** all board data (cards, containers, items, positions, sizes, colors) lives in one state object, so undo, copy-paste and saving work the same way for everything.
4. **Tests:** automated tests for the logic (overlap, snapping, checklist moves, undo) plus browser tests for the main flows. All tests pass before a change is accepted. Tests are written first: for each change, write its tests, see them fail, then build it.
5. **Small steps:** build one section of this spec at a time, show it working, then move on. Keep a short changelog in the repo.
6. **No surprises:** do not add features that aren't in this spec without asking first.
7. **Keep this spec current:** whenever the owner asks for a new feature or change, or a decision is made, update this spec in the same step so it always describes the app as it is.

## Board and navigation

The board is an endless canvas with a dotted 20px grid under a fixed top toolbar.

**Toolbar, left to right:** Boards button (see "Several boards") · the path to the open board, when it is inside another · board name (editable, box sized to its text; in a narrow window it and the path shrink first, the name down to 140px, ending in …, so no button is pushed off) · Hand / Select tool toggle · Undo · Redo · | · "Add": Note · Checklist · Container · | · Color (its menu also holds Auto-color) · Arrange · File · Feedback (signed in only: a speech-bubble icon and the word Feedback; it opens Send feedback, see "Delete your account" and "Send feedback") · | · Appearance (a half-filled circle; opens the menu with the Dark mode switch and the color themes, see "Look and feel"); on the published site, Share (an icon of two people, see "Sharing and editing together") and | · Sign out at the far right (an icon button: an arrow leaving a door, with the tooltip "Sign out"). (| = a thin divider between groups.) In windows up to 1500px wide the toolbar's gaps and button text tighten, so every button, Sign out included, fits a 1280px window, also inside a sub-board. Locally, `npm run dev` with `?signed-in` in the address shows Sign out, to check the fit. Note, Checklist and Container (its accessible name is "New container") look alike: outlined buttons, each with its own icon (there is no Add Link: new cards are notes and checklists only; link cards already on a board, or made by an import, still work as described below). **Arrange** (owner decision 2026-10-16) opens a small menu under it holding Snap to grid, Collapse all, Same width and Clean up, each with its label; the menu stays open while its buttons are used, and a click anywhere else closes it. Escape closes the Arrange or File menu and puts focus back on its button. Arrange and File have no border until hovered. On the published site Share is the one solid honey button. A zoom control (Fit to screen · − · percentage · +) sits bottom-right; Fit to screen (or Shift+1 outside text fields) brings every card and container into view, as large as fits, centered (zooming in up to 100%, or out as far as 30%); clicking the percentage resets to 100% around the center of the screen. Left of it: A− / A+ (text size on cards and containers: six steps: Small 90%, Normal 100%, Large 115%, Larger 130%, Huge 150%, Largest 175% (owner request 2026-10-19); the toolbar keeps its size; remembered on this device, not synced, not undoable; A− / A+ fade at the ends; a value saved before the two new steps still loads, an unknown one falls back to Normal; the per-text sizes below are separate and unchanged), and, further left, a round ? button that opens a Keyboard shortcuts panel listing every shortcut (also opened and closed by the ? key outside text fields; Escape, its ×, or a click outside closes it). Right of ?: a round coffee-cup button, "Buy me a coffee", that opens the owner's Buy Me a Coffee page (https://buymeacoffee.com/ezcookie) in a new tab; on a phone it is in the ⋯ menu. Left of ?, one pill holds the side-panel buttons, each an icon with a short label (owner decision 2026-10-16): Search (opens Find), Completed (the Completed panel, see "Clean up and the Completed panel"), History (Version history), Timer (the Focus timer, see "Focus timer"; while it runs it shows the time left instead) and, for someone signed in, Calendar (Google Calendar, see "Google Calendar") and, for everyone, Journal (opens the Journal panel with today's note, see "Daily journal"; owner request 2026-10-18) and, last, Habits (opens the Habits panel, see "Habits"; owner request 2026-10-19). So, left to right: the panel pill · ? · coffee cup · A− / A+ · zoom.

| Action | How |
| --- | --- |
| Pan the board | Hand tool: drag empty space. Any tool: scroll or trackpad swipe, which moves the board half the scroll distance (mouse wheels that scroll by lines or pages count a line as 16 px and a page as the board area's height) |
| Zoom | Ctrl + scroll or trackpad pinch, centered on the cursor; Ctrl + = / Ctrl + − / Ctrl + 0 to reset (these also work while typing, so the browser never zooms the page instead). On a touch screen, two fingers pinch to zoom and move together to pan, anywhere on the board including over cards; a pinch cancels whatever the first finger had started (such as dragging a card). Also on a touch screen, on the empty board only (owner request 2026-10-18): a double tap zooms in one step and a long tap zooms out one step, each around the finger and by the same step as the zoom buttons (see "Phone layout"). Phones use the phone layout below. Range 30%–250% |
| Rectangle select | Select tool (V): drag on empty space; anything the rectangle touches is selected live |
| Switch tools | H for Hand, V for Select |
| Snap to grid | Toggle in the toolbar's Arrange menu (on a phone, in ⋯), on by default. Moves, resizes and pastes land on 20px steps. Snapping happens where a block lands, not while it moves (see Moving). Turning it back on moves every block (position and resized sizes) to the nearest grid point |

- With the Hand tool, the cursor is an open glove over empty board and a closed glove while dragging the board. Otherwise (Select tool, and over cards and containers with either tool) it is the normal arrow. Text fields show the text cursor.
- New cards and containers never appear on top of existing blocks. From a toolbar click they appear at the free spot nearest the middle of the screen.
- Edge panning: while dragging a block, dragging checklist items, selecting items by press-and-drag, or drawing a selection box, holding the pointer within 48px of the edge of the board area keeps moving the board that way (faster nearer the edge), and the drag carries on as if the pointer had moved. A drag that starts near an edge only does this once the pointer has been away from the edges.
- Alignment guides: while dragging a card or container (or several selected ones together, which line up as one: the box around them all), when its left edge, middle or right edge (or top, middle or bottom) comes within 8px of the same line of another block on the board, it snaps onto that line and a thin amber guide shows across both blocks. A guide wins over the grid on its axis. Blocks the dragged one is on top of are left out (they are about to move aside). Not while resizing (sizes match instead).
- Add Note, Add Checklist and New container can also be dragged from the toolbar onto the board. A dashed outline shows where the block will appear (the free spot nearest the pointer); a new card dragged over a container goes into the container at the pointer (a new container never does). Letting go off the board adds nothing.
- Opening the board (desktop and phone) shows every card and container, centered on the screen. The remembered zoom is kept when everything fits at it; otherwise the board zooms out just enough, but not below 50% so text stays readable. If the board is still too big at 50%, its top-left part is shown. This also happens when the online copy first arrives on an empty screen. The tool always starts as Hand.

### Several boards

- There can be any number of boards. The first board is the **home board**, which can't be deleted. Each board has its own cards, containers, name, Snap setting and undo history: Ctrl+Z never undoes something on another board (except in the Journal panel, where it undoes on the Journal board only; see "Daily journal"), and switching away and back keeps a board's undo history (until the page is reloaded).
- **Boards button** (a two-boards icon at the left of the toolbar, after the ant; on a phone, in the top bar) opens a menu listing every board (except the hidden Journal and Habits boards, see "Daily journal" and "Habits"): the home board first with the boards inside it indented under it (and theirs under them), then each board that isn't inside another. The open board is highlighted. Clicking a board opens it. Every board except home has a × that deletes it, after a confirmation.
- **Add a sub-board here** (in the menu; on a phone also + → Sub-board) makes a new, empty board inside the open one: a **board card** appears on the open board (placed like a new card: into a selected container, else at the free spot nearest the middle of the screen), selected. A board card shows the board's name ("Untitled board" until it is named), how many cards are on it, and **Open board**; double-clicking the card opens it too. It can be moved, put in a container, collapsed (showing the name), resized, copied (the copy opens the same board), and deleted like any card: deleting the card leaves the board itself in the Boards menu.
- **New board** (in the menu) makes a new, empty board on its own (not inside another) and opens it. A new board that is left empty and unnamed, and that no card opens, is dropped when another board is opened.
- Opening a board shows every card and container on it, as when the app opens. Which board is open is remembered on each device (not synced), so the app reopens there.
- **Path back up:** on a board inside another, the boards above it show before its name, smaller and grayed ("Home › Trips ›"); clicking one opens it.
- **Ctrl+arrow keys switch boards** (not while typing in a text field; the Control key, not ⌘): Ctrl+→ / Ctrl+← open the next / previous board in the Boards menu order, sub-boards included (as if the whole list were open), passing over the hidden Journal and Habits boards (see "Daily journal" and "Habits"); Ctrl+↑ opens the board above (the one before the name in the path); Ctrl+↓ opens the first board inside the open one. At the ends, and with no board above or inside, nothing happens (no wrap). A short note (the same banner as other notes, gone after about 2.5 seconds) says "Switched to <board name>". They are listed in the ? shortcuts panel. On a Mac, Control+arrows are usually taken by the system (Spaces), so they may never reach the page.
- **Deleting a board** removes it and every board card that opens it, on every board; boards inside it are kept and then stand alone. Every board is saved in Version history first, so a deleted board can be brought back from there. If the deleted board is open, the board above it opens. A shared board is the exception: only the person who shared it can delete it, and it is deleted for everyone (see Sharing and editing together); a "couldn’t be deleted" note shows if that fails.
- Ctrl+A, Clean up, Collapse all, Fit to screen and Download as text work on the open board only; Search too, unless its "All boards" switch is on (see "Search"). Copy and paste work between boards.

### Daily journal

Owner request, 2026-10-18 (first a button that opened a board called "Journal"; changed the same day: "the journal shouldn't open up in a new board, rather it should open up in a side panel like the pomodoro"). The writing is kept on an ordinary board called "Journal", one dated note card a day, so saving, sync, undo and backups work as for any board; the Journal button shows it in a side panel instead of opening that board.

- **Journal button** (a closed book with the label "Journal"): in the panel pill by the zoom control, just before Habits; on a phone a Journal tile in the ⋯ panel's top tiles, just before Habits. Pressing it opens the **Journal panel** in the side panel spot, shared with Version history, Completed, the Focus timer, Google Calendar and Habits (one at a time; full screen on a phone). Escape (a first Escape leaves the text box), its × or the button again closes it. The board being looked at stays open behind it: nothing is opened, moved or selected on it.
- **The panel** shows today's note first, with the cursor at the end of its text, ready to type, and the earlier days below it, newest first. Each day is its date as a small heading over a text box in the card colors (white, dark in dark mode) that grows with its text; earlier days can be edited too. Today's note is first even when a later date has been written ahead. Keys pressed while the keyboard is anywhere in the panel (a text box, its heading or blank space, which a click keeps it in) never act on the board behind it (Delete, arrows, copy and paste, Ctrl+D and the like do nothing there); only Ctrl+Z / Ctrl+Y (below) and the zoom keys work. Opening the panel clears the selection on the board, so nothing selected there can be deleted by a key meant for the journal. The heading is the note's first line and is not edited in the panel. Notes on the Journal board without a date line are not shown.
- **The Journal board** is the first board named exactly "Journal" (capital J, nothing else) among the person's own boards, in the Boards menu order. A board held by a share (their own shared boards, or ones shared with them) is never used. If there is none, the first press makes one, on its own: no card is added to home or any other board. While it isn't yet known which boards are shared (published site, just after opening), the button changes nothing and says "Your shared boards are still loading. Try again in a moment."
- **Hidden:** a Journal board that no card opens and that holds only dated notes (no containers, no other cards) is not listed in the Boards menu, and Ctrl+arrow keys pass over it, unless it is the open board. While it isn't yet known which boards are shared, nothing is hidden. A Journal board that has a card opening it (as the Journal button used to make, on home) or anything else on it stays listed and opens as any board does.
- **Today's note** is a note card whose text starts with today's date in the calendar's style with the year, on its own line ("Sun 18 Oct 2026", local time), then a blank line; what is typed in the panel goes under the date. Opening the panel adds it if it isn't there: straight above every other block on the Journal board, level with the leftmost one, so the newest day is on top and nothing moves (as it grows, the notes below are pushed down as usual when that board is drawn). A note whose first line is today's date followed by a space and more text (a title typed after the date) counts as today's note; changing the date on the board makes it another day's note, and the next opening adds a new one.
- **Undo:** the Journal board keeps its own undo history, as every board does. Adding today's note is one change and typing is merged as on the board. Ctrl+Z / Ctrl+Y while the keyboard is in the panel undo and redo on the Journal board only, whichever board is open behind it; Ctrl+Z on the board itself undoes that board as usual. Undo in the panel never changes another board.
- Boards already saved are not changed: nothing happens until Journal is pressed, a board someone already named Journal is used as it is, and an existing Journal board and its card on home are left where they are.

### Habits

Owner request, 2026-10-19 ("a new feature for habit tracking"). Daily habits, kept like the journal on an ordinary board, called "Habits", so saving, sync with the signed-in Google account (or on the device when not signed in), undo, Version history and backups work as for any board; the Habits button shows them in a side panel instead of opening that board.

- **Habits button** (three small day boxes, two ticked, with the label "Habits"): the last button of the panel pill by the zoom control, after Journal; on a phone a Habits tile, the last in the ⋯ panel's top tiles. Pressing it opens the **Habits panel** in the side panel spot, shared with Version history, Completed, the Focus timer, Google Calendar and the Journal (one at a time; full screen on a phone). Escape (a first Escape leaves a text box), its × or the button again closes it. The board being looked at stays open behind it, and opening the panel clears its selection. As in the Journal panel, keys pressed while the keyboard is in the panel never act on the board behind it; only Ctrl+Z / Ctrl+Y (below) and the zoom keys work.
- **The panel**: a "New habit" box at the top (it has the cursor when the panel opens, except on a phone or touch screen, where it waits for a tap so the keyboard doesn't cover the day boxes; Enter or Add adds the habit at the end of the list; a blank name adds nothing), then each habit as a white card (dark in dark mode): its name, editable in place, a delete button (bin icon), a row of seven day boxes for this week, Monday to Sunday (the weekday's letter over the date; today's box has an accent border), and its streak below ("No streak", "1-day streak", "5-day streak"). With no habits it says "No habits yet. Add one, then tick each day you do it." Habits are listed in the order they were added (the Habits board's order: if that board is opened and its cards are moved, the list follows it); they can't be reordered in the panel.
- **Ticking:** a day box ticks that day (filled green) or unticks it. Any day of this week can be ticked, a day ahead too; each day is ticked at most once. Day boxes are at least 44px tall (52px on a phone) and share the card's width; each is named for screen readers with the habit and the day ("Read, Mon 19 Oct").
- **Streak:** the number of days in a row ticked, ending today, or ending yesterday while today isn't ticked yet (today isn't over, so not having ticked it yet doesn't break a streak that ran through yesterday). Days ahead of today don't count. Days before this week count too: the streak runs back as far as the ticks do.
- **Version history:** restoring a version rolls the Habits board back to how it was then, as with the Journal (owner decision 2026-10-19); a version without a Habits board leaves it as it is.
- **Delete** asks first ("Delete the habit "Walk" and its ticks? You can bring it back from Version history, or with Ctrl+Z in this panel."); Ctrl+Z in the panel or Version history brings it back with its ticks.
- **Undo:** the Habits board keeps its own undo history. Adding, ticking, unticking and deleting are one change each; typing a new name is merged as on the board. Ctrl+Z / Ctrl+Y while the keyboard is in the panel undo and redo on the Habits board only, whichever board is open behind it; in the New habit box they undo the typing instead, as it isn't saved yet. The toolbar's Undo button acts on the open board, as with the Journal.
- **How it is stored:** each habit is a checklist card on the Habits board, its title the habit's name, with one ticked item per ticked day whose text is that day ("2026-10-19", local date); each habit also keeps the blank item every new checklist has. A day item unticked on the Habits board itself doesn't count as ticked; ticking that day again ticks the same item. When two devices change habits while offline, the Habits board syncs whole like the person's other boards, so the last save wins (only on a board in a share are the two merged, and then a day ticked on both counts once). The panel always uses the Habits board as found right now, so one that arrives from another device while it is open is the one shown.
- **The Habits board** is the first board named exactly "Habits" among the person's own boards, in the Boards menu order, never one held by a share. Opening the panel makes nothing: the board is made, on its own (no card on home or any other board), when the first habit is added. While it isn't yet known which boards are shared, the button changes nothing and says "Your shared boards are still loading. Try again in a moment."
- **Hidden:** a Habits board that no card opens, that isn't the home board and that holds only habits (checklists whose items are all ticked days or blank, no containers, no other cards) is not listed in the Boards menu, and Ctrl+arrow keys pass over it, unless it is the open board. A Habits board with anything else on it, or a card opening it, stays listed and opens as any board does; only its habits show in the panel.
- Boards already saved are not changed: nothing happens until a habit is added, and a board someone already named Habits is used as it is.

### Importing from other apps

**File** (toolbar; on a phone under ⋯) opens a menu:

- **Download backup:** every board (every card, position, size, color and setting) in one file, named like "BusyAnts - Home - 2026-10-05.json" ("All boards" in place of the name when there are several).
- **Download as text:** the open board as readable Markdown (a board card is written as "Board: its name"): its name, each container (left to right) with its cards, then the loose cards top to bottom; to-do items as "- [ ]" / "- [x]", sub-items indented.
- **Restore from backup…:** pick a backup file; after a confirmation it replaces the board. A backup of one board, with one board here, replaces the open board: the board as it was is saved in Version history first, and Ctrl+Z brings it back. A backup of several boards (or any backup while there are several boards here) replaces every board, after asking "Replace all your boards…?": every board is saved in Version history first, and undo starts over. A backup made before there were several boards replaces the open board. A file that isn't a BusyAnts backup changes nothing and says so. The restored board is brought into view. Boards someone else shared with this person (the shared board and every board inside it) are never replaced or removed by a backup: they stay as they are, a board in the backup with the same id is left out, and a note says so ("“Trip” is shared with you, so it was left as it is."); a backup can't make one of them the home board. Boards this person shared are restored like their own.
- **Import file…** (on a phone, in the File menu under ⋯): pick a file from another app: Markdown (.md, .markdown: Milanote, Obsidian, Notion, Bear…), text (.txt), a web page (.html, .htm: Evernote or Google Keep exports, saved pages), a JSON export (.json: a Trello board, Google Keep notes from Google Takeout) or a PDF (.pdf). The kind of file is worked out from its name and content. Its cards are added to the current board; nothing already there is changed or replaced.

On an iPhone with BusyAnts on the home screen, the downloads open the Share sheet (Save to Files) instead.

**Markdown** (a Milanote export reads as it always has, except that bullet lines right under a heading now become list items):

- Each heading becomes a checklist with that title; a heading with nothing under it becomes an empty list. A "# name" line at the very top of the file (the board or page name) is ignored, and so is a "---" block of settings at the top (Obsidian).
- Checklist lines ("- [ ]", "- [x]", "* [ ]") become the list's items, keeping sub-items (up to 6 levels) and ticks; ticked top-level items go into "Completed". A blank line between items starts a new list with no title.
- Plain bullet and numbered lines ("- a", "* a", "1. a") right under a heading, or inside a list, also become items (not ticked). Elsewhere they stay part of a note.
- Other text becomes a note (paragraphs kept; bold, strike-through and escape marks removed; links shown as "text (address)"). A note that is only a web address becomes a link card, titled by a heading right above it.

**Text:** a .txt file with headings or checklist lines in it is read as Markdown. Otherwise each block of text between blank lines becomes its own note (a block that is only a web address becomes a link card).

**Web pages (HTML):** h1–h6 become checklist titles; lists (ul / ol / li) become items, keeping nesting; a ticked checkbox in an item ticks it; each paragraph becomes its own note (a heading right above it starts the note, line breaks kept); a paragraph that is only a link becomes a link card; links inside text show as "text (address)". Scripts, styles, menus (nav), the page head, comments, noscript, template, iframe and svg are ignored, and so is a heading with no text (such as a logo). Only web addresses (http, https) are shown after a link's text; other links keep just their text. The page is only read as text: it is never shown, its scripts never run and its pictures and other files are never loaded.

**JSON (Trello, Google Keep):**

- A Trello board export: each open list (in Trello's order) becomes a checklist titled with its name; its open cards become items, ticked when the card is marked complete in Trello; a card's checklist items become its sub-items with their ticks (a card with several checklists gets one sub-item per checklist, its items under it). A card's description becomes a note (the card's name on its first line) placed after its list. Archived (closed) lists and cards are left out; a list with no cards becomes an empty list. Labels, dates, members and attachments are not brought in.
- Google Keep notes (one note per file, or a file holding a list of notes): a list note becomes a checklist titled with the note's title, keeping its ticks; a text note becomes a note, its title on the first line; a text note that is only a web address becomes a link card titled with the note's title. Notes in the bin are left out; archived notes come in.
- Any other JSON, or a .json file that isn't valid JSON (including a BusyAnts backup, which goes through Restore from backup…), adds nothing and says "BusyAnts can only import JSON files from Trello or Google Keep."
- All of it is read as plain text: nothing in the file is run, shown as a web page or loaded.

**PDF:** only the text is read; layout, pictures and tables are lost. A file is read as a PDF by its .pdf name or its content.

- Lines clearly bigger than most of the text (and not too long) are headings: the title of the checklist below them, or the first line of the note below them (an empty checklist when nothing follows). A heading over two lines stays one.
- Bulleted lines ("•", "-", "*", "1.", "1)", and the bullets Word puts in PDFs) and checkbox lines ("☐", "[ ]" unticked; "☑", "☒", "✓", "[x]" ticked; similar marks work too) become items of a checklist titled by a heading right above (or untitled); a line indented under an item is a sub-item, and a wrapped item line joins its item.
- Other text becomes notes: a heading right above starts the note, the lines of a paragraph are joined into one (a word broken with "-" is joined keeping the "-"), and separate paragraphs are lines of the same note; a list, a heading or a new page starts a new note. A note that is only a web address becomes a link card. A page number alone at the top or bottom of a page, set apart in the margin and no bigger than the text, is left out.
- A PDF with no text in it (a scan, or only a page number) adds nothing and says "That PDF has no text BusyAnts can read (it may be a scan), so nothing was added."
- The PDF reader (pdf.js) is loaded only when a PDF is imported, so the app's first load doesn't grow. All of the file is read as plain text: nothing in it is run, shown or loaded.

**Every import:**

- The file has no positions, sizes or colors: cards are laid out loose in up to 4 lanes 20px apart (each card at the bottom of the shortest lane, in file order), starting at the top middle of the screen, or the nearest free space (the board then pans to show them). Once drawn, the lanes are tidied to the cards' real heights.
- The imported cards are selected, so they can be dragged or deleted together. One undo removes the whole import. A file with nothing in it adds nothing.
- A file it can't read (another kind, such as a picture, or a broken or password-locked PDF) adds nothing and says "BusyAnts can’t read that file yet." A file over 5 MB is refused with a short note. At most 300 cards and 2,000 checklist items come in from one file; a longer file adds its first part and says so.

## Blocks: cards and containers

The board holds three card types and containers that stack cards. Cards show no type label; the type is told by content. Cards are always white (loose or in a container); only containers are colored.

**Naming** (owner decision, 2026-10-16): people read "container" everywhere: the toolbar, menus, tooltips, screen-reader names, shortcuts, the tour, the website and this spec. Only what people read changed. Code names, CSS classes, test ids and the saved board format keep "column", so saved boards are untouched; the Claude connector (`mcp/`) also still says "column" in its answers and its `column` setting.

| Block | Content | Color |
| --- | --- | --- |
| Note | Free text; grows taller as you type, never scrolls | White |
| Checklist | Title plus checklist (next section) | White |
| Link | Title, URL field, "Open <domain>" button in a new tab | White |
| Container | Title (box sized to its text), card count, stacked cards | Neutral stone-gray until recolored |

**Headers:** cards show a collapse arrow and a small trash can (the same icon and faint color as a checklist item's, red on hover) at the top right (no "2/5 done" count); hovering them shows what they do ("Collapse card", "Delete card (Ctrl+Z brings it back)"; containers the same). With a mouse, these header buttons (collapse arrow and trash can, on cards and containers) show only while the pointer is over that card or container, while it is selected, or while one of its fields or buttons has the keyboard focus (owner decision 2026-10-16); they stay in place while hidden, so nothing shifts. On a touch screen wider than a phone they always show; on a phone (under 600px) they show only on the selected card or container (see "Phone layout"). There is no title band (owner decision 2026-10-16): cards are white with a bold title, loose or in a container; a color picked in the Color menu tints the header lightly (see "Collapse, add, delete, color"). Containers show the title and count at the left, and the collapse arrow next to the trash can on the right. No move handles and no per-block palette icons.

**Moving**

- Drag any blank part of a card or container to move it; a drag starts after a 5px nudge so a click still just selects.
- The dragged block stays flat (no tilt) with a 2.5px amber border and soft glow.
- Dropping a card fully onto a container inserts it at the pointer position; the container opens if collapsed. Dragging a card out of a container makes it loose.
- **A checklist dropped on another checklist pours into it** (owner request): drag a whole checklist so the pointer is over the body (title or items, not the top strip) of another loose checklist; that list gets the dashed amber outline and nothing is pushed aside. Letting go moves all the dragged list's items to the end of it, with their sub-items, order and ticks (ticked ones into its Completed section; top-level items with no text anywhere in them are left out), and the dragged list, title included, is gone; the list that took them is selected. One undo brings it back. Lists inside a container don't take a dragged list (dropping there puts it into the container as usual), and nor do collapsed lists, notes or links; several blocks dragged together never pour.
- While dragging, the block follows the pointer exactly; a dashed amber outline shows the grid spot it will land on, and on release it glides there (160ms). Blocks pushed aside also glide. No gliding when the computer is set to reduce motion.
- **The dragged block takes priority, and rows keep together** (owner decision 2026-10-19, "Spring back + row shift"): it lands on the grid spot under the pointer, and blocks in its way make room, previewed live while dragging (except over a list it will pour into, above). Room is made only for where the block is now, worked out from where everything was when the drag started: once it has moved past a block, that block springs back to its own spot. Blocks in the same row as the dragged block (they overlap it by at least half the shorter one's height) slide sideways and keep their left-to-right order, pushing the row-mates beyond them along: those whose middle is left of the dragged block's middle go left, the others right (on a tie, the way the dragged block came from, so dragging a block onto its neighbour swaps them; straight up or down, right). Only row-mates level with the ones being pushed are pushed along, so blocks stacked beside the dragged one move over together. Other blocks in the way move to the nearest free spot. A single dragged card never pushes a container: over a container it drops in, and where it would otherwise cover one it takes the nearest free spot (and its row is not shifted for a spot it won't take). Dragged containers push everything. Several blocks dragged together push what is in their way to the nearest free spot (no row shift).
- **No overlap, ever:** loose blocks keep at least a 10px gap. When a container grows, a block is pasted or a size changes, anything it would cover moves to the nearest free spot. Resizing a block by hand works like dragging (owner decision 2026-10-19): when it is let go, blocks in its row slide right (a block only grows to the right), keeping their order (nothing moves while the edge is still being dragged, so shrinking it again before letting go leaves them where they were). When a block grows (expanding, typing, a container filling up), blocks below it (their top level with or lower than its top) are pushed straight down instead, and so are blocks below those; blocks beside it still take the nearest free spot.

**Resizing**

- Loose cards: bottom-right corner handle sets width and minimum height (content taller than that still grows the card). A collapsed loose card can still be resized: a right-edge strip sets its width, and its corner handle sets width and height (down to just its header, 40px). A collapsed loose card starts as tall as a collapsed container (60px), so collapsed blocks line up; one made taller keeps its header in the middle. Its collapsed height is kept separately, so expanding it gives back its open size, and collapsing it again gives back the collapsed size.
- Containers: corner handle and right-edge strip set the width; cards inside follow it. A collapsed container keeps its right-edge strip, so its width can still be changed. On collapsed cards and containers the strip is tinted on hover. A container with cards is always exactly as tall as its cards (so collapsing cards shrinks it); only an empty container has a minimum height, which the corner handle also sets.
- Cards inside a container cannot be resized and size to their content.
- Keyboard: a resize handle reached with Tab resizes with the arrow keys: → / ← 20px wider / narrower, ↓ / ↑ taller / shorter (corner handles only); Shift for 100px. Each press is one undo step.
- While resizing, the edge follows the pointer and eases to the grid size on release; the size label shows the final size.
- Size limits: cards 200–1280 wide, containers 240–1280 wide (owner choice 2026-10-16; was 640), heights 100–700. "Same width" and the keyboard resize use the same limits. Boards already saved are not changed.
- Size matching: within 8px of another block's width or height, the size snaps to match; matched blocks get a dashed amber outline and a label shows e.g. "240 × 180 · same width as 2 blocks". Otherwise sizes snap to the grid when snapping is on.

**Collapse, add, delete, color**

- Collapse arrow: a card shrinks to one line with a preview (first line, list title, or link title), shown in the middle of the card when it is loose; a container hides its cards.
- Collapse all (in the toolbar's Arrange menu; on a phone in ⋯): if any card or container is open, collapses every card and container; when everything is collapsed it reads Expand all. With cards or containers selected it acts on just those (a selected container with its cards), and on everything only when nothing is selected. Collapsing closes the gaps (Collapse all, and also collapsing a single card or container with its arrow): each block below a collapsed one moves straight up by as much as that block shrank, keeping the spacing it had under it (the mirror of growth pushing straight down); blocks to the side and big deliberate gaps stay as they were. Expand all opens every card and container (also ones that were collapsed before Collapse all). Straight after Collapse all it also puts every block back where it was, unless it was moved in between; whatever an opening block grows into is pushed straight down (the higher block keeps its place). One undo step each. Faded on an empty board.
- Same width (in the Arrange menu, after Collapse all; on a phone in ⋯): the selected loose cards and containers all take the width of the first one selected (within each kind's size limits; cards inside containers follow their container). One undo step; anything they now cover moves out of the way. Faded with fewer than two selected.
- Expanding a card or container can push nearby blocks aside. Collapsing it again puts those blocks back where they were (in the same undo step), unless one has been moved since or its old spot is now taken. This is remembered until the page is reloaded.
- Adding a card with a container selected puts it at the end of that container; with a card inside a container selected, directly below that card; otherwise loose on the board. New checklists and containers start untitled, showing a "List title" / "Container title" placeholder (a list made by dropping items on the board too). A new checklist starts with one blank item and the cursor in its title; Enter there moves the cursor to the first item. A new note gets the cursor in its text, a new container in its title. An empty board shows a centered hint ("Add a note, a checklist or a container from the toolbar, or drag one onto the board. Press ? for keyboard shortcuts."; on a phone: "Tap the Add button (+) below to add a note, a checklist or a container.") until anything is on it. Escape leaves the field and keeps the block selected.
- The container's trash can opens a small confirmation saying what goes ("Delete “Ideas” and its 3 cards?", or "Delete “Ideas”?" when it is empty; for several containers "Delete 2 containers and their 5 cards?") · Keep container · red Delete container, and then deletes the container and all its cards.
- Toolbar Color recolors every selected container from 24 swatches (three rows of 8 large 32px chips, table below: two rows of soft pastels, then a row of 8 bold, clearly different colors, each ringed in its own edge tone; if the open menu would cover the block being colored, the board moves down so it stays in view), plus Default (back to stone-gray). The name of the swatch under the pointer (or of the current color) shows under the swatches. For selected cards, which stay white, it lightly tints their header instead (and a checklist's or link's title just under it): 60% of the swatch's background mixed with the card's own color, with the usual dark ink (at least 7:1 on every color, light and dark mode); on a bold color the header's icons and the empty title's placeholder use the color's own text color (at least 4.5:1). A note gets the tint across its header strip. Default takes the tint off. A card in a colored container is not tinted unless it is given a color itself. The Color button opens its menu even with nothing selected; the swatches and Default are then faded and do nothing.
- Auto-color, a button at the bottom of the Color menu (below the swatches and Default), gives every container on the board a different color in one step (undoable). Containers are taken left to right, and colors handed out in this order so neighbors differ clearly, the bold colors first: Ocean, Tomato, Emerald, Violet, Sunflower, Magenta, Grass, Tangerine, then the pastels Sky, Peach, Mint, Lavender, Butter, Teal, Rose, Lime, Periwinkle, Coral, Aqua, Orchid, Sage, Sand, Slate, Stone. Colors repeat only beyond 24 containers. It works with nothing selected, and is faded when there are no containers. There is no separate Auto-color button on the toolbar or in the phone ⋯ panel.

### Text formatting

- Every text box can be formatted as a whole: card titles (checklists and links), note text, checklist items and container titles. Not a link's address, nor the board name. Formatting always covers the whole box, never single words.
- Choices: size Small / Normal / Large (Normal is the usual size; they scale with A− / A+, so Large stays larger than the text around it), **bold**, *italic*, and a typeface: Plex Sans (the usual one), Serif, Rounded, Handwritten, Typewriter. No colors.
- Highlighting any text in a box shows a small bar just above it with B, I, the three sizes and a Font menu (each font shown in its own style). Its buttons format the whole box; hovering the bar outlines what it will change. With checklist items selected, the bar shows above them and formats all of them.
- While typing: Ctrl+B bold, Ctrl+I italic, Ctrl+Shift+> larger, Ctrl+Shift+< smaller, on the box you are in (with or without highlighting). With checklist items selected, they format those items; with whole cards or containers selected, every text box in them. Bold and italic turn on for all unless all already have it, then off for all.
- Formatting is saved with the board, syncs, is one Ctrl+Z step, and is kept by copy, duplicate and paste. Enter keeps it on both halves of a split item (and on the new item below); joining two items keeps the first one's formatting. Ticked items and items in the Completed panel keep it. Text copied to other apps is plain.

## Checklists

A checklist is an editable title plus a tree of items up to 6 levels deep, with finished top-level items gathered in a Completed section.

**Items**

- Item text is edited in place and wraps onto new lines at the width of the card, less the strip kept free at the right for the hover buttons (described below); no focus rectangle.
- Enter works like a text editor. At the end of an item it adds a new item directly below: right after it, or as its first sub-item if it has sub-items. In the middle of the text it splits the item: the text after the cursor moves into a new item directly below (placed the same way; one space at the split is dropped; any sub-items stay with the first half; a ticked item stays ticked in both halves), with the cursor at its start. At the very start of an item with text it adds a blank item right above, and the cursor stays with the text. Selected text is removed first. There is no "Add an item" field and no add or sub-item buttons.
- Tab nests an item under the one above; Shift+Tab moves it out a level. Backspace on an empty item deletes it (a list's last item cannot be deleted this way). Delete with the cursor at the very end of an item pulls the item shown below it up into it: its text is joined on (cursor stays at the join) and its sub-items move up one level into its place. It never pulls an item across from the open list into Completed.
- On hover, each item shows a Move up arrow (22px wide), a Move down arrow (22px), a trash can (28px) and a drag grip (18px), all 28px tall, in that order, at the right end of its first line, in a 92px strip every item keeps free for them, so they never cover the text and the text never moves on hover. None shows otherwise (a keyboard-focused one shows too, with a focus ring). The arrows do what the phone's Move up / Move down buttons and Ctrl+Shift+Up / Down do (next bullet), in one undo step, and leave the cursor in the moved item; at the top or bottom of the item's level its arrow is faded and does nothing. On a touch screen (no hover) the arrows never show (the phone has its row above the keyboard) and the strip stays its old, narrower width (40px), with the trash (24px) and grip (14px) at their old, smaller sizes; the grip shows only on the item being typed in, where it drags with a finger, and so does the trash can on a tablet; on a phone there is no trash can on the row (see Phone layout).
- Up / Down arrows move between items as if the list were one long text: Up goes to the end of the item above, Down to the start of the item below. Inside a multi-line item they move line by line first. Items hidden in a collapsed Completed section are skipped.
- Ctrl+Shift+Up / Down move the item being typed in (with its sub-items) past the item above / below at the same level, keeping the cursor in it. A top-level item never passes into or out of the Completed section; at the top or bottom of its level nothing happens.
- Ctrl+Enter (⌘+Enter on a Mac) in an item ticks it, exactly as clicking its Done box does (the same move into Completed, sub-item rules, selected items and one undo step); on a ticked item it unticks it and the cursor stays where it was. After a tick the cursor moves to the nearest open item below it in the same list, or else the nearest one above; with no open item left it leaves the field and the list stays selected. It never splits the item or adds one.

**Completed section**

- Ticking a top-level item moves it and its sub-items into the "Completed" section at the bottom (its header shows no count, and collapses and expands the section). Ticking a sub-item only strikes it through, except that ticking the last open sub-item of an item ticks that item too (and so on upwards), so a list item whose sub-items are all done moves to Completed. Unticking a sub-item unticks the items it is nested in.
- **Uncheck all** (on the same line as "Completed", at the right; shown while anything in the list is ticked and the Completed section is open; owner decision 2026-10-16) unticks every item and sub-item in the list, so a list such as groceries can be used again. One undo step.
- **Ctrl+Shift+Backspace** (with the Control key on a Mac too, since ⌘+Shift+Backspace there is the browser's Clear browsing data; not while typing in a text field) deletes every item in the Completed sections of the open board's lists, with their sub-items. Other boards (sub-boards too), open items, ticked sub-items under open items and the Completed panel are left alone. It always asks first, below the toolbar in the container confirmation's style: "Delete 12 completed items?" ("Delete 1 completed item?"; the count includes sub-items) · Keep · red Delete. Escape keeps them, and other board keys wait until it is answered. Delete is one undo step: Ctrl+Z brings them all back. A list left empty gets one blank item. With nothing completed, nothing is deleted and a short note, "No completed items on this board", shows for a moment. On a shared board it works like any other edit. It does nothing while an old version is being looked at.
- **Clean up** (just left of Uncheck all; likewise shown only while the Completed section is open) does the Arrange menu's Clean up for this list only: its ticked items (the Completed section and ticked sub-items) move into the board's Completed panel under today's date (see "Clean up and the Completed panel"); other lists are left as they are. The list stays selected. One undo step. On a card too narrow for all three, Clean up and Uncheck all go on the line below, still at the right.
- Web addresses (http://, https:// or www.) typed in a note show as links under its text (the address without https:// and www., opening in a new tab); Ctrl+click (⌘+click) on an address in a note or a checklist item opens it too.
- With motion allowed, an item on its way to Completed shows ticked and eases down and out (280ms) before moving, then fades in at its new place with a brief amber tint (450ms). With reduced motion, or when a key did it (Ctrl+Enter, or the keyboard on the Done box), it moves at once. Undo right after ticking undoes the tick.
- Trash deletes that item and everything nested under it. If a list becomes empty, a blank item replaces it.
- Exception: deleting an item with no text (trash, Backspace or Delete) keeps its sub-items if any of them has text; they move up one level into its place. Cut (Ctrl+X) always takes sub-items with the parent.

**Dragging items**

- Drag the grip to move an item and all its sub-items: before/after another item (amber line), nested under an item (drop slightly right; amber tint), into another list, or onto empty list space (appends; the whole card, top included, gets a dashed amber outline).
- Dropping on empty board space (or on a note, link or open container) creates a new untitled checklist at that spot with the dragged items (the dragged label says "Drop to make a new list"). Dropped on a collapsed checklist, they go in at its end (ticked ones into Completed); it stays collapsed and gets the dashed amber outline while they are over it. Dropped on a collapsed container, they become a new untitled checklist at the end of that container, which opens.
- A list emptied by the drag (every item dragged out, one at a time or several selected, into another list or onto the board) is gone, title or not, and the list that took them is selected. One undo brings it back.
- **Lifting an item on a phone (owner request 2026-10-19, job 114).** On the phone layout (under 600px wide, by finger), resting a finger on a checklist item (its text included) for about half a second lifts it, and moving then drags it with its sub-items, with the same drop rules as the grip (before, after or under another item, into another list, onto empty list space, onto the board as a new list). The grip still drags at once. While it is held: the item leaves its place; its label is drawn as a floating row, as wide as the item, with a shadow under it, on the finger's line a little above it and kept on the screen (the label of a grip drag on a computer is unchanged); the rows slide smoothly aside, up to close the space the item left and down to open a gap of its height where it would land (in another list too; over empty board or over nothing only the first happens); and the board's edge panning works as for the grip. Letting go drops it where the gap is, and the rows stay where they slid. A quick tap on an item still types, and a finger that moves before resting moves the board, as for a card. Resting on the list's title, the card's blank parts or a note still picks up the whole card. Windows 600px and wider (tablets too) are unchanged: resting on an item picks up the card. Only `transform` and `opacity` move (the label moves by `translate`, never `left` / `top`); with the computer set to reduce motion the rows jump at once and the label does not grow in. The cursor is not changed (build rule 6). The drag is view only until the drop: the drop is the usual one undo step.

**Selecting several items**

- Hold the mouse on one item and drag over others to select a range, across open and completed items. Shift+click extends the range; with no range yet, Shift+click selects from the item being typed in to the one clicked. A range can span items at different levels. Selected items get a amber text highlight and a lighter row tint. No action bar.
- With several selected: Backspace or Delete removes them all; ticking any one ticks them all (unticking one reopens them all); the trash on any one deletes them all; dragging any one moves them all, in order, with their sub-items; Ctrl+C / Ctrl+X / Ctrl+V copy, cut and paste them after the selection. Copy and cut take exactly the highlighted items (a sub-item that isn't highlighted is left out, and cut leaves it in the list, moved up into its parent's place), and also put their text on the computer's clipboard for other apps: one item per line in the order shown, indented two spaces per level below the least-indented highlighted item; Tab / Shift+Tab move them all in or out one level together (one that can't move, such as the first item of a list, stays and the ones after it nest under it) and they stay selected; Escape clears.
- Ctrl+A, pressed again and again, selects more each time: first the text of the item being typed in; then every item in that list (from some of a list's items, the whole list); then every item in every list in the same container (skipped for a loose list); then every item on the board. Only items you can see are taken: none from collapsed cards or containers, nor from a closed Completed section. Escape or clicking empty board clears.
- Pressing on an item and dragging down or up into another card of the same container carries the selection on through those cards (never into other containers or loose cards).
- With items selected in several lists: Delete / Backspace, ticking and the trash work on all of them (a list left empty keeps one blank item); Ctrl+C copies them, putting each list's title on its own line with its items indented two spaces under it, in board order (containers left to right, each top to bottom, then loose lists top to bottom, left to right). Tab, Ctrl+X, Ctrl+V and dragging do nothing then.

### Clean up and the Completed panel

- **Clean up** (in the toolbar's Arrange menu; on a phone in ⋯) moves every ticked checklist item on the board into the board's one **Completed** record: ticked top-level items (the Completed sections) and ticked sub-items under open items, each with everything nested under it. Lists left empty get one blank item. It is faded when nothing is ticked, and is one undo step. Nothing new appears on the board, and the panel does not open by itself.
- The record is shown in the **Completed panel**, not on the board (owner decision 2026-10-15, Job #51). The Completed button (a ticked box with the label "Completed") in the panel pill by the zoom control (on a phone ⋯ → Completed), opens and closes it. It shares the right side panel spot with Version history, the Focus timer, Google Calendar, the Journal and Habits (one at a time; full screen on a phone); Escape or its × closes it. Each board has its own record. Items are grouped under the date Clean up was clicked ("2 Oct 2026"), newest date on top; cleaning up again on the same day adds to that day. Each item shows the list it came from, and its sub-items as they were. Before any Clean up it says "Nothing cleaned up yet".
- The record is kept in the board data as before (the saved format is unchanged). A board saved with a Completed card on it keeps the card's items, but the card is no longer drawn and takes no space: nothing else moves, and in a container it is left out of the count, the drop places, moving a card up or down the container and "Delete container" questions. Select all, box select and Fit to screen pass over it. It can never be deleted and is never copied.
- Unticking an item in the panel sends it back, unticked, to the list it came from: under the item it was nested in if that is still there, otherwise at the end of the list. If that list is gone, a new list with the old title is made at the free spot nearest the middle of the screen. An emptied day disappears. Each untick is one undo step.

## Selection, clipboard and undo

Every block action works on one block or on a whole selection, and every change can be undone.

| Shortcut (⌘ on Mac) | Does |
| --- | --- |
| Click | Select one block (amber outline); click empty space to clear |
| Ctrl + click (or Shift + click) | Add or remove a block from the selection |
| Select tool drag | Rectangle selection; hold Ctrl to add to the current selection |
| Ctrl + A | Select every container and loose card (with checklist items selected, selects more items instead; see "Selecting several items") |
| Ctrl + C, then Ctrl + V | Copy and paste the selection (a container copies with its cards, titled "… copy"); pastes offset by 40px each time |
| Ctrl + D | Duplicate the selection |
| Delete / Backspace | Delete the selection; if it includes a container, the same confirmation as the container's trash can appears first, then containers go with their cards |
| Ctrl + Shift + Backspace (Control on a Mac too) | Delete every item in the Completed sections on the open board, after asking (see "Completed section") |
| Drag a selected block | Moves the whole selection together |
| Arrow keys | Move the selected loose cards and containers one grid step (20px); Shift + arrow moves five. Like a drag, they keep their spot and whatever is in the way moves. A single selected card inside a container moves up / down its container instead (← / → do nothing). Presses in quick succession are one undo step |
| Ctrl + Z | Undo, up to 100 steps, from anywhere including inside text fields; a burst of typing counts as one step |
| Ctrl + Y | Redo (Ctrl + Shift + Z does nothing) |
| Escape | Clear the selection and close menus. While typing in a card or container, Escape leaves the text field and keeps the block selected, so the arrow keys then move it |

- Undo and Redo buttons in the toolbar fade when there is nothing to undo or redo.
- Keyboard shortcuts for blocks do not fire while typing in a text field, except undo, redo and zoom.
- **Custom hotkeys** (owner request, job 118, 2026-10-19). The keys for seven actions can be changed in the Keyboard shortcuts panel: Hand tool (H), Select tool (V), Select all (Ctrl+A), Copy (Ctrl+C), Paste (Ctrl+V), Duplicate (Ctrl+D) and Delete selection (Delete; Backspace always deletes too). In the panel (the ? button or ? key) each of these rows shows its key as a button; clicking it shows "Press a key…" (and a note under the heading that Escape cancels); the next key pressed becomes the new key. A key is one character (a letter, digit or symbol) or Delete, alone or with Ctrl (⌘ counts the same) and/or Shift; Alt is not offered (Alt+arrows jump between cards). The match is exact, so Ctrl+Shift+D no longer duplicates once Duplicate is Ctrl+D. A key that can't be used is refused with a short note under the heading and nothing changes: one another action already has ("V is already used by Select tool."), one the app keeps (undo, redo, zoom, bold and italic, find, cut, ? with or without Shift, Shift+1: "… is already used by the app."), Ctrl+A / Ctrl+C / Ctrl+V for any action but their own (checklists use them too: "… is used in checklists."), ones the browser keeps (Ctrl+T, W, N, Q, R, L, P, S, O, U, J, H, G and Ctrl+1 to 9: "… is kept by the browser."), and any other kind of key (Enter, Tab, arrows, Escape, Space, function keys: "That key is used for something else."). To swap two keys, move one out of the way first. A **Reset to defaults** button in the panel's heading puts all seven back. Fixed, not changeable: undo and redo (they keep working inside text fields), zoom, Shift+1, ?, Escape, the arrows and Alt+arrows, Ctrl+arrows, Ctrl+B / I / F / X, text sizes, and every key inside checklists (Ctrl+A / C / X / V on items stay Ctrl). As before, none of the seven fire while typing in a text field. The Hand and Select buttons' names and tooltips show the current key ("Hand (G)"). The choice is a **device setting**, like dark mode: saved in this browser's localStorage under `note-board:hotkeys` as JSON, never in board data, never synced to other devices, never undone, and left alone when an account's data is cleared from the device. A missing, damaged or unusable saved value (an unknown action, a key the rules above refuse, or two actions on the same key, in which case every action goes back to its default) means the usual keys.

## Keyboard navigation between cards

- Up / Down arrows move through every text field of a card (note text, list title and items, link title and address). Inside a container they carry on into the card above or below and select it. Collapsed cards are skipped; loose cards don't continue to other cards.
- Alt + arrow keys jump to the nearest card or container in that direction by on-screen position (loose or in a container), select it, put the cursor at the end of its first field and pan it into view. Only a card or container lying wholly that way counts (one mostly below is reached with ↓, never →); one straight ahead (level with it for ← / →, above or below it for ↑ / ↓) beats one off to the side, then the nearest wins. Containers are stops at their title strip: ↑ from a container's top card goes to the container (cursor in its title), ↓ from there to its first card, ← / → from a title to the next container's title; empty and collapsed containers are reached the same way. With nothing selected they start from the card or container nearest the middle of the screen. Works while typing.
- Ctrl + arrows keep moving word by word in text. Alt + ← / → never make the browser go back or forward a page.

## Sign-in, sync and offline (published site)

- The published site updates when the owner says "publish", or by itself shortly after a low-risk pull request (one that doesn't touch saving, sync, undo or deleting) is merged and passes its tests.

- The published site shows only a "Sign in with Google" screen until someone signs in; sign-in is remembered on each device. It is open to everyone: any Google account (with a verified address) can sign in and gets its own private board, synced across that person's devices, which no one else can see, except boards they share (see Sharing and editing together). Under the button: "Your board is saved online with your Google account so it opens on all your devices. Only you can see it." The online rules only accept the fields the app saves, and a board (or a saved version) of at most 900,000 characters; a refused save shows the usual "Couldn't save online" banner. An account the rules turn away anyway is told "This Google account can't open a board" and offered Sign out.
- Every board of a person's own is stored in Firebase (project `note-board-a672a`) in one document per user (shared boards are stored apart, one document per shared board: see Sharing and editing together), holding the same data as the browser save (so the 900,000-character limit is for all of a person's boards together). Which board is open isn't synced. A single board sent by an older version of the app (still open somewhere) only replaces the home board; the other boards are kept. Firestore security rules (`firestore.rules`, pasted into the Firebase console by the owner) allow only the owner's account to read or write it.
- First sign-in: the online board wins; if there is none, this device's board is uploaded. After that, changes reach other devices within a second or two, and the most recent change wins. A change from another device clears undo history and waits for any drag in progress to finish. A change made on this device that hasn't been uploaded yet, or a drop made after the other device saved, counts as more recent: it is kept and sent, and the other device's version is dropped. If the online board can't be read (damaged, or saved by a newer version of the app), it is never shown or overwritten: the page shows "Your board couldn't be loaded" and stops syncing until reloaded. If an upload is refused (for example the board is too big for Firebase), a small red note at the bottom says "Couldn't save online. Changes are on this device only." The next change tries again; the note goes once an upload succeeds, and until then changes from other devices are not applied. Changes are also uploaded straight away when the window is hidden or minimized, not only when it is closed.
- Works offline: once visited online, the page opens without internet (signed in, it opens on this device's copy, including edits not yet sent, offline or just after a reload; job 92; if those unsent edits are over the 900,000-character online limit, the red "Couldn't save online" banner shows as soon as the board opens and they stay on this device, as with any refused upload, job 94); edits are kept on the device and uploaded when the connection returns. A small gray note left of the bottom-right controls says "Saving…" while a change waits to upload, "Saved" once it is online, and "Offline. Will save when you’re back online" without a connection (the red banner shows instead when a save fails). A new version of the site replaces its offline copy, so new icons and files reach returning visitors.
- Installable as an app: in Edge or Chrome the site can be installed (address-bar Install button), giving BusyAnts its own window without an address bar, a Start menu and taskbar icon (a simple chibi ant silhouette on warm yellow), and the same sign-in, sync and offline behavior. - **Delete your account (job #63, required by Google Play; owner decisions 2026-10-16).** Signed in, File → Delete account… (on a phone ⋯ → File; shown in red, last in the menu) opens a panel that says plainly what is deleted (their account, everything kept online except feedback they sent, and the copy on this device; it can't be undone; other phones or computers they're signed in on are signed out but keep the copy saved on them until it's cleared, owner 2026-10-16): all their boards (with how many), version history kept online, the boards they shared (how many: deleted for everyone they shared them with, with the boards inside them, exactly as deleting a shared board does), the boards shared with them (how many: they leave them, the others keep them), their name and photo on shared boards, and their sign-in (their Google account itself stays). (job #69).

## Sharing and editing together (being built, owner request 2026-10-05)

Several people can work on the same board at once, on the published site. Built in steps; this section says which are done.

- **Sharing by link (done, step 2).** The Share button (two people, beside Sign out; on a phone in ⋯) opens a panel for the open board. Any board except the home board can be shared ("Your home board holds all your other boards, so it can’t be shared"): Share this board makes a link, shown with Copy link. Anyone who opens the link and signs in with Google (the sign-in screen then says "Sign in to open the board shared with you.") gets that board and every board inside it, sub-boards added later included; it opens straight away, with no "Join this board?" question (owner decision, 2026-10-06), and stands alone in their Boards menu. Shared boards have a small two-people mark in the Boards menu. The panel lists the people who have it (photo or initial, "(you)", and "Shared it" beside the person who shared it); everyone it is shared with sees the link and can copy it (owner confirmed, 2026-10-06). Changes reach everyone’s screen within a second or two.
  - Only the person who shared it can turn the link off (no one new can join; "Turn link on" makes a new link, and old copies of the link stop working for good), remove someone (after a confirmation; it goes from their screen with the note "“Trip” is no longer shared with you."; if the link is on, it changes in the same step, so the copy the removed person has never lets them back in; a link turned off stays off), rename the shared board (its name box is read-only for the others), delete it (Boards menu, after a confirmation: it is deleted for everyone, who see "“Trip” was deleted by the person who shared it."; boards inside it stay with the person who shared it), or restore an old version of it ("Only the person who shared this board can restore it." shows instead of Restore). Everyone else can change everything on it, sub-boards inside it included, and can Leave this board (after a confirmation).
  - A link that was turned off (or is wrong) shows "This share link doesn’t work. It may have been turned off: ask for a new one." Notes like these show under the toolbar until closed with ×.
  - Online, a shared board (with the boards inside it) is one Firestore document, `shared/{id}` (at most 900,000 characters), apart from the owner’s own boards (`boards/{uid}`, which no longer holds it); `shared/{id}/members/{uid}` lists who has it and `boards/{uid}/shared/{id}` which shared boards each person has. The rules (`firestore.rules`, pasted into the Firebase console by the owner) let only those people read or change it, let someone join only with the current link, and let only the person who shared it change the link, remove people or delete it. Each save counts up by one, so a page can’t save over a version it hasn’t seen. Until the new rules are pasted in, sharing shows "That wasn’t allowed…" and everything else works as before.
  - When a shared board goes from someone's device (they are removed, they leave, or it is deleted), every board is first saved in their Version history, so it can be brought back from there as a board of their own. Leaving happens online in one step: if it doesn't work, nothing changes and the panel says "That didn’t work. Check your connection and try again." (the same note shows when any other change in the panel fails). If deleting a shared board fails, a note says "“Trip” couldn’t be deleted. Check your connection and try again."
  - Until the device knows which boards are shared (the list of shared boards hasn't answered yet), a board on it that came with a shared board kept on the device, or one made meanwhile, is left alone: it is neither sent with their own boards nor removed by a version from their other devices. Other boards left on the device still give way to the online copy on first sign-in, as above. A shared board this version of the app can't read, and never opened on this device, doesn't hold this up: it isn't opened (its link says "This share link doesn’t work…"), it is left as it is online, and the person's own boards sync as usual (whole-app review, 2026-10-17). If it was saved by a newer version of the app (its version number is above this app's), it stays on the list of everyone it is shared with, including someone opening the link for the first time, so an updated app opens it. If it is damaged, in the old single-board format or saved by an older version, it is treated like one without its starting board: someone opening its link who isn't its owner and wasn't on it before (that link-open added them) is taken off it again; someone already on it keeps it, even on a new device; if the server can't say whether they were on it (no connection, say), nobody is taken off (job 98, 2026-10-18). One already opened here stays as it was until a version it can read arrives.
  - Changes made offline are kept on the device and sent when the connection returns, combined with what others did meanwhile; so are changes made just before the page was closed. The version last agreed with the server is kept on the device for this, and so is the list of shared boards the device has, so they are known as shared as soon as the page opens, before the server answers.
  - **A share never takes your own boards** (security review, 2026-10-06). A shared board only ever holds the boards in its own online data, plus sub-boards made inside it on a person's own screen (with the boards inside those). Whatever anyone saves in it online can't take, replace or delete one of the boards of the person who opens it: a board card in it pointing at one of your boards doesn't bring that board in (even once moved to another of its boards), and nor does a board card you paste or move onto it that opens a board that was already one of yours: only a sub-board made inside the shared board joins it; the card just opens your board, for you only (main session check, 2026-10-06), a board in it with the id of one of yours is left out on your screen (your own stays as it is; the one exception: the first time the person who shared it opens it on another of their devices, the share takes over that device’s old copy of the board and the boards inside it), and a link whose shared board is one of your own doesn't open ("This share link doesn’t work…"). A later version without its shared board isn't taken (the boards stay as they were). The shared board itself can't go from a device by any other way than deleting or leaving it: if it does (undoing its making, say) it comes straight back, and its deletion is never sent to everyone. A deleted share's records of who had it go with it, and a page that finds someone else's share under a deleted one's id treats it as deleted.
- **Edits are combined (done, step 1: `src/model/merge.ts`).** When two people change a board at the same time, every change to different things is kept: different cards, different parts of one card (its text and its position, say), different checklist items, cards both added to one container. Only when both change the very same thing (the same text box, the same card's color) does the later change win. A card or item one person deletes while the other is changing it is kept, so nothing typed is lost. The combined board always keeps the board's rules (every card in one place, every item in one list).
- **Undo (planned, step 3).** Ctrl+Z undoes only your own changes, and changes from other people no longer clear undo history.
- **Who's here (planned, step 4).** Small round photos of everyone who has the board open; a colored outline with the person's name on any card or container they're typing in or dragging.
- **Version history (planned, step 5)** for shared boards: for now every page keeps its own versions (holding the shared boards too), and only the person who shared a board can restore it.

## Version history

- Like Google Docs, earlier versions of the board are kept and can be looked at and restored. On a computer it opens from the History button (a clock with the label "History") in the panel pill bottom right; on a phone from ⋯ → Version history.
- A version holds every board. A version is saved automatically: when editing starts again after 10 minutes without an edit on any board, every board as it was just before is saved (and during a long stretch of editing, once an hour). Undo and redo count as edits; blocks re-arranging themselves don't. A version that couldn't be saved (offline, say) is tried again a minute later. The board on screen is always the "Current version". Changes arriving from another device don't save a version there (that device saves its own). A version the same as the newest one isn't saved again. The newest 100 versions are kept online; a board kept on one device only (no sign-in) keeps 20, since each is a whole copy of the board and device storage is small.
- On the published site, versions are kept online with the board (shared by every device the owner signs in on); otherwise, on the device.
- The list shows "Current version", then earlier versions grouped by day (Today, Yesterday, then the date), newest first, each with its time and what was on the boards (e.g. "12 cards · 3 containers", or "2 boards · 12 cards · 3 containers").
- Picking a version shows the open board as it was then (empty if it didn't exist yet), read-only: the board can be moved around and zoomed, but nothing can be changed. A bar shows when it was saved, with Back to current and Restore this version. Escape goes back to the current board, then closes the history. On a computer the list stays at the right; on a phone it fills the screen and steps aside while a version is shown (Back to current brings the list back).
- On a shared board only the person who shared it can restore (see Sharing and editing together). This holds however a restore is started: restoring a version or a backup file never changes a board that is in a share someone else shared with this person (the same note as for a backup says so; a one-board backup while such a board is open says "Only the person who shared this board can restore it." without asking). This holds from the moment the page opens: the shares this device kept from last time count straight away; while it isn't yet known which boards are shared with this person (neither this device nor the server has said, or a share's boards haven't arrived yet), nothing is restored or saved and the note says "Your shared boards are still loading, so nothing was restored. Try again in a moment." (for a backup file, before asking). Restoring first saves every board as a version (so nothing is lost; the save starts at the press, before the chosen version is read, and offline the restore waits at most 3 seconds for it: the version stays queued on this device, even over a reload, and is saved once back online), then puts the open board back as it was in the chosen version, as one change: Ctrl+Z (or Undo) brings back the board from before the restore. Boards deleted since that version come back too (they stand alone in the Boards menu), and so do the hidden Journal and Habits boards as they were then (see "Daily journal" and "Habits"; each as one change on its own undo, so Ctrl+Z in that panel takes it back; a version from before one existed leaves it as it is); other boards are left as they are. If, before it goes ahead, the person goes back to the current board, picks another version, or another board opens, nothing is restored. If that save is refused before the restore happens (within the 3 seconds, or while the chosen version is still being read), nothing is restored and the bar says "Couldn’t restore it. Try again."; if it is refused later, after the restore, a note says "The boards from before your restore couldn’t be saved in Version history."

## Focus timer (owner request 2026-10-06)

- A Pomodoro timer for focused work. The Timer button (a stopwatch with the label "Timer", or the time left while it runs) in the panel pill by the zoom control (right of History; on a phone ⋯ → Focus timer) opens it in the **side panel**, a plain panel at the right of the board. It shares that spot with Version history, Completed, Google Calendar, the Journal and Habits, one at a time (opening one closes the other), and fills the screen on a phone. Escape, its × or the button again closes it; an Escape meant for something else (leaving a text box, closing the shortcuts list, canceling a "Delete …?" question) leaves it open.
- The classic cycle: a 25-minute focus round, then a 5-minute short break, and after every 4th focus round a 15-minute long break, then round 1 again. The panel shows which it is ("Focus · Round 2 of 4", "Short break · Round 2 of 4"), the time left in large figures (25:00), and **Start** (**Pause** while running), **Reset** (back to the full length of this round, stopped) and **Skip** (on to the next round straight away, counted as done).
- When a round ends, the next round is set up at its full length and waits for Start. A short, soft chime plays (made in the browser, no sound file), unless "Chime when a round ends" is unticked in the panel. If the tab is behind another, a browser notification also shows ("Focus round done" / "Break over", with what comes next), once notifications are allowed: the browser asks once, on the first Start. Skip and Reset don't chime.
- It keeps running with the panel closed: the stopwatch button then widens to show the time left (18:42), also while paused; on a phone the ⋯ line shows it. It keeps going across a page reload (the time the round ends is kept, not a counter); a round that ended while the page was closed has moved on when it opens, without a chime.
- The lengths (Focus, Short break, Long break, whole minutes from 1 to 120) can be changed in the panel; a stopped round takes the new length at once, a running or paused one keeps the time it has left. A box left with anything else goes back to the length in use. Lengths, the chime setting and the timer are remembered on this device (`note-board:pomodoro`), the same for everyone using this browser: not part of any board, not undone by Ctrl+Z, not synced. Missing or damaged saved values fall back to the defaults, and a saved round with more than 120 minutes left (the computer's clock was wrong) starts again as a stopped first focus round. With BusyAnts open in two tabs, each follows what the other does with the timer, and only one chimes.

A day shows up to 3 lines, or 2 when the cells are under 70px wide (a window under about 810px wide, a phone under about 490px wide), where only names show (the time is in the hover text); when more events than that, the last line says "+2 more". Switching from Month to Week starts the seven days on the month's selected day (today, a day clicked, or after ‹ / › the same date in the month shown).
- **Panel width** (owner request 2026-10-16): the calendar panel opens **420px** wide in the Week view and **720px** in the Month view (the other side panels, Version history, Completed, the Focus timer, the Journal and Habits, stay 300px). On a computer a thin strip on its left edge (`role="separator"`, "Resize calendar", with a column-resize cursor, the only place it shows) can be dragged to make it wider or narrower; with the strip focused, ← widens and → narrows by 20px, and a double-click puts that view's usual width back. It is never under 300px and never more than the window's width minus 300px, so 300px of board stays visible; if the window shrinks it narrows with it (and comes back when the window grows). Week and Month each remember their own width on this device (`note-board:calendar-width`, like `{"week":420,"month":720}`): not board data, not undone, not synced; a missing or bad value is the usual width. The zoom control and the Find bar move aside with the panel's width. A phone is full screen with no strip. An event's name in the Week view, and in the list of the day picked in the Month view, may wrap onto a second line (then it is cut with …).
- **The person's own events** (they organise it, no reminders of its own, not one of Google's special kinds) can be changed, also when repeating or with guests (owner request 2026-10-16, job #85): the + beside a day adds one (an hour from 9:00 that day), clicking one opens a form with Title, All day, Starts (date, time), Ends (date, time) and **Guests**; changing the start date moves the end date with it, so moving an event keeps its length. Save sends it to Google; an end not after the start says "The end must be after the start." **Delete** asks first, in the container confirmation's style: "Delete “Dentist”?" · Keep · red Delete.
- **Guests:** the form lists the event's guests by email address (not the person themself), each with a × "Remove guest …" button, and a "Guest email" box with **Add** (Enter adds rather than saves). Something that doesn't look like an email address says "That doesn’t look like an email address." and isn't added; an address still in the box when Save is clicked is added first (or stops the save with that note). New events can have guests too. The guest list is sent to Google only when it changed; guests already there are sent back as Google gave them (with their answers). When the event has guests (before or after the change) and is saved or deleted, the form then asks "Send update emails to guests?" · Don’t send · **Send** (Google's `sendUpdates=all` / `none`); without guests nothing is asked or sent about emails. Escape on any of these questions goes back to the form without saving.
- **Repeating events:** saving one first asks "Save changes to which events?" · Cancel · **Only this event** · **All events in the series**; deleting one asks "Delete “Team stand-up”?" · Keep · Only this event · All events in the series. All events applies to the whole series only what was changed in the form, each event keeping its own day: a new title; a new start time (with the form's length); a new length or end alone (from the series' own start); guests added or removed (the series' other guests stay). What wasn't changed stays as the series has it, so a time, title or guest this one event was given on its own (say 10:00 in a 09:00 series) doesn't spread to every event (2026-10-17). The event being edited, when it was changed on its own before (moved, or it differs from the series on its day in title, time or guests), also gets the new title and guest changes itself, keeping its own time, since Google may leave such an event out of the series' change (2026-10-17). That event's own change is sent before the series', since the series' new time can give it a new id; if the series' change then doesn't reach Google, the form stays open with "Only this event changed: the rest of the series didn’t reach Google Calendar. Try again later.", and saving again sends both (job #88). A title changed only by spaces isn't a new title, and an untitled event's "(No title)" is only shown, never saved as its name. An event made all-day, or timed, on its own when its series isn't can't be changed as a whole here: All events says "This event was changed to or from all day on its own: change all of the series in Google Calendar." and changes nothing; when the start date was moved or All day was switched, only Only this event is offered, with "Moving it to another day, or to or from all day, changes only this event." A timed series Google keeps in another time zone than the device's can't be changed as a whole here: All events says "This series is in another time zone: change all of it in Google Calendar." and changes nothing. While any of these questions is open, the form behind it can't be edited. Deleting the whole series removes every event of it, also ones changed on their own, as Google Calendar does (owner decision, 2026-10-17). The repeat rule itself can't be changed here, and there is no "this and following".
- Other events (someone else's, ones with their own reminders, Google's special kinds like Out of office, or ones whose guest list Google left out because it is too long) are shown read-only, marked with a small open-in-new icon: clicking one shows its day and time, says they can only be changed in Google Calendar, and has **Open in Google Calendar** (a new tab; only links into Google Calendar are opened).
- Calendar events aren't board data: they are not undone by Ctrl+Z, not in Version history, not saved with or synced as boards. Several calendars, answering invites, changing the repeat rule, reminders and links to board cards are not in this version.
- **Access:** calendar permission (`calendar.events`) is asked for only when the panel first opens, not at sign-in, through Google's own window (Google Identity Services, whose script loads once the button shows, so the click opens the window without a wait that browsers would block); after agreeing once, a fresh access (about an hour each) comes without asking. It is used only for the same person with over a minute left, and dropped on sign-out and when another person signs in (by the sign-in code loaded at start, so also before the calendar has ever shown, and in every tab, as Firebase tells them all), when Google refuses it, when it runs out, and when the account is deleted; anything damaged or of the wrong shape there (an expiry that isn't a finite number included) is ignored and Google is asked as before. A copy kept for the tab by the earlier version (`sessionStorage`) is moved to this device if it passes the same checks, else removed. It is never in a backup or export (those hold board data only). Limit: Google's quick window still shows about once an hour of use, when the access runs out, and on another device. Trade-off: anything that could run script in the page, or another page on the same address (`ezhang43.github.io`), could read it until it runs out, up to about an hour, also after the tab is closed (docs/decisions.md, 2026-10-19, job 107). When there is no calendar access yet because Google's window was blocked, didn't open or was closed, the panel says "Google’s window didn’t open or was closed. Click Connect Google Calendar to try again."; when access was refused (or calendar access unticked), "Calendar access wasn’t given. Click Connect Google Calendar to allow it."; both with a solid **Connect Google Calendar** button, which asks Google again straight from the click (so its window isn't blocked). When the calendar can't be reached for another reason (no client ID set, offline, a Google error), the panel shows one plain note, "Google Calendar isn’t connected yet. Try again later.", with **Try again**; a change Google refuses says "That change didn’t reach Google Calendar. Try again later." (the form stays open). Nothing else is affected. The permission is unchanged by guests and repeating events: `calendar.events` covers them.

- A local MCP server (`mcp/`, built to `mcp/dist/server.js` by `npm run mcp:build`) lets Claude Desktop and Claude Code read the owner's boards and change checklist items and add notes on their own ones. Plan and the owner's decisions: `docs/plans/mcp-connector-plan.md`; setup steps: `mcp/README.md`. It is not part of the web app.
- **Sign-in:** `npm run mcp:login` opens a page on this computer only (localhost, a random port, a one-time code in its address) with **Sign in with Google**; the Firebase refresh token is saved in `%APPDATA%\busyants-mcp\token.json` and swapped for an id token (1 hour) when needed, so `firestore.rules` apply as in the app. `npm run mcp:login -- --key <key>` uses a second API key instead of the app's web key (for when that key only works from the site's address). `npm run mcp:logout` deletes the file; the running connector reads the saved sign-in on every call, so a logout stops it reading at once and a new sign-in is used without restarting it. Claude Code may not read it (deny rule in `.claude/settings.json`).
- **Tools (read only):** `list_boards` gives each board's name, id, the board it sits inside, home or shared ("shared by Erika, read-only"; "shared by you" for one the owner shared) and its counts of columns, cards and open items. `read_board` (by id, or by name when only one board has it; otherwise it lists the choices) gives an outline: columns left to right with their cards top to bottom, then loose cards top to bottom; checklists with ticks, nesting, ids and their Completed section; notes (quoted), links, board cards and the Completed record (shown in the app as the Completed panel). Failures (not signed in, sign-in expired, key restricted, permission denied) come back as plain error text.
- **Check:** `npm run mcp:check` reads only and prints the account, the board count (and how many are shared) and "Safe to edit: yes / no (reason)": yes only when the saved data reads as boards and writes back exactly as it was (`safeToEdit`), so a later version that changes boards never drops data from a newer app. With no sign-in it says "Not signed in. Run npm run mcp:login first." and fails.
- **Tools that change boards (job B, 2026-10-07):** only on the owner's own boards; a shared board is refused ("shared boards are read-only for this connector"), also one just shared whose old copy is still in the owner's own boards. Boards and checklists are named by id, or by name when only one has it (otherwise the choices are listed); items by id. Each call is one save and answers with a plain list of what changed ("Saved:" then one line each, with new items' and notes' ids), or an error, with nothing saved.
  - `add_items(board, list, items[{text, after?, under?}])`: at the end of the checklist, right after an item (several after the same item keep their order), or as the last sub-items of an item. Text is one line (line breaks become spaces), never blank.
  - `edit_items(board, changes[{item, text}])`: new text. There are no due dates (removed 2026-10-16): a `due` sent to `add_items` is ignored, and `edit_items` changes only text.
  - `set_items_done(board, items[], done)`: ticks or unticks, as clicking the box does (the last open sub-item ticks its parent).
  - `move_items(board, items[], to{list, after? | before? | under?})`: with their sub-items (each list's items in the order shown, lists in the order their items were given), to a checklist on the same board; never next to or under themselves. A list the move empties keeps one blank item (the connector never deletes anything).
  - `add_note(board, text, column? | near?)`: at the end of a column (id or title), just below a card in a column or beside a loose card or column (`near`: its id), or else loose near the top left, never over another block. Notes can only be added, not edited.
  - Items nest at most 6 levels. At most 50 changes per call and 5,000 characters per item or note text.
- **Saving a change:** the connector reads the owner's boards, makes the change with the app's own rules (`src/model/`), and saves only if every board still passes `problems(board)`, the boards are safe to edit (`safeToEdit`; old, damaged or newer-app data is refused) and the saved text is at most 900,000 characters. It saves `data`, its own `client` name (`mcp-…`) and the server's time, only if nothing was saved since it read (Firestore's `updateTime` condition); if something was, it reads again and makes the change on top, at most 3 more times, then gives up ("the boards kept changing"), saving nothing. Nothing in Firestore is ever deleted.
  - **Safety version:** before its first change (and again when a change comes after 10 quiet minutes, or an hour after the newest version, as the app's version rule), the boards as they were are saved as a version (board text first, then its list entry, never over an existing one), unless the newest version already holds exactly that (`contentHash`). If the version can't be saved, the change isn't made.
  - **Put back:** 5 seconds after saving it reads the boards again. If the app saved over the change (own boards sync "most recent wins"), it makes the change once more on top (same ids, so nothing doubles) and says so; if it is saved over again, the answer says the change isn't on the board now, and it isn't tried a third time. If the board changed so the change no longer applies (its list deleted, say), the answer says so and nothing is put back. Known limit: if the owner changes the same item in the app within those seconds, the connector's change is put back over it.
  - **Activity log:** every save is added as a plain line with the time to `%APPDATA%\busyants-mcp\activity.log`.

## Search

- Ctrl+F (also while typing in a card) opens the board's own search bar instead of the browser's; so does the Search button (a magnifier with the label "Search") at the left of the panel pill (bottom right), and ⋯ → Search on a phone. The bar sits at the top right (across the top on a phone).
- It looks in container titles, list and link titles, checklist items (sub-items and ticked items too), notes, link addresses and the Completed panel, ignoring upper / lower case. Matches are taken in board order: containers left to right (their cards top to bottom), then loose cards top to bottom.
- Every match is marked in yellow inside the text, the current one in orange; the bar shows e.g. "2 of 7", or "No matches". Enter / ↓ / the down arrow button go to the next match, Shift+Enter / ↑ / the up arrow button to the previous one (wrapping round). The board moves so the current match is in the middle of what can be seen (above a phone's keyboard), zooming in to 100% first if the board is zoomed out below 60%.
- A match out of sight (in a collapsed card or container, or a closed Completed section) marks that card or container with an orange ring instead, and the count says "in a closed card"; nothing is opened by itself. A match in a link address rings the address box.
- Matches in the Completed panel come after all the others. While the panel is shut, the current one rings the Completed button and the count adds "in Completed"; the panel is not opened by itself. While it is open, the match is marked in the panel and scrolled into view.
- Escape or × closes the bar and the marks go.
- **This board / All boards** (owner request 2026-10-19, job 102): under the box a two-option switch, "This board" and "All boards" (two toggle buttons; 28px tall on a computer, 44px on a phone; the bar's colors). The bar opens on "This board" every time it opens, and the choice is view state: never saved, not undoable. Escape or × closes the bar and the next search starts on "This board" again (Ctrl+F while the bar is already open keeps what is chosen). Clicking an option leaves the cursor in the box, so Enter still steps.
  - **All boards** counts matches on every board the person has, sub-boards and the hidden Journal and Habits boards included, with the same match rules as above (board names themselves are not searched). The open board comes first, then the other boards in the Boards menu order (sub-boards under their board); inside a board, board order as above. The order is fixed when the box, or the switch, last changed, so stepping through it does not reshuffle it when a match opens another board. A board that is not among the person's boards (a shared board they can't open) is not searched.
  - The count reads e.g. "3 of 12 · Garage" while the current match is on another board that is not open (for example the first match when the open board has none); the board does not move until you go to the match (Enter or Shift+Enter first goes to that current match). Enter / ↓ / the arrow buttons go to the next match, and Shift+Enter / ↑ / the up arrow to the previous one (wrapping round, across boards); a match on another board opens that board the way the Boards menu does (same undo and selection behavior), then the board moves to the match and marks it as above. Opening a board by hand does not change the list.
  - Searching only reads: it never changes or saves a board. (Opening a board by search has the Boards menu's one side effect: leaving a new, empty, unnamed board that nothing opens discards it, as the menu does.) Going back to "This board" limits matches to the open board again.
