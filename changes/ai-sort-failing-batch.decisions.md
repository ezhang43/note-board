- 2026-11-15 (job "ai-sort-failing-batch", owner approved the fix from the code review; worker's calls, flagged for the owner). (1) **Record, don't split.** A batch that fails in a way that would repeat (`refusal`, `too-long` or `bad-reply`: the three that come only from a reply Anthropic gave, the same three Test key counts as "Anthropic answered") has every item saved as asked with no label (`SAME_AGAIN` in `src/store/aiLabels.ts`), then the sort stops there with the failure's message, as before. Splitting the batch and retrying the halves was not chosen: it adds requests (counted uses) the person did not press for, and breaks the spec's "a failure is never retried by itself" and "50 per request" rules. The cost: up to 49 items that would have been fine in another batch keep their built-in category with that model; another model or Forget key asks again. This narrows the 2026-11-13 call "a failed or cancelled batch is not saved" (job viz-ai-autosort) to failures that may pass next time. (2) **Everything else saves nothing:** no key, the monthly cap, the use counter, labels not saved, every HTTP error (key, permission, limits, rate limit, model, too big, update, busy, other), no connection, time-out and Cancel; a refusal that comes back after Cancel or a key or model change is not saved either. `too-big` and `update` (both errors from Anthropic, likely not charged by Anthropic but counted as a use here) can still repeat once per open; left out of scope. (3) If those "asked" marks cannot be saved, the sort reports the labels-not-saved message, so Sort automatically pauses as for any label save that fails. (4) The failure messages ("Try different text", "Try with less text", "Try again") are unchanged, though a second press now sends the items behind, not the same ones. (5) **Room probe left as it is** (finding 12, unproven): `fits()` writes and removes its test in one synchronous call, so nothing in this tab (a board save included) can run while it is there; every `storage` listener in the app matches its own key exactly (`POMODORO_KEY`, the AI settings keys, the journal key's ending, or a full clear), so another tab ignores the probe's events; and a board save that did fail in another tab is retried on its next change, with the board still in memory and online. `navigator.storage.estimate()` does not measure the localStorage quota, so swapping to it would weaken the boards' room (BOARDS_ROOM) rather than keep it.
