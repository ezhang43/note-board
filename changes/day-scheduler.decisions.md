- 2026-11-11 Day scheduler model (`src/model/schedule.ts`, nothing calls it yet): a block the app made is an event with `block: { cardId }`, defined in that file until tagging is built. Only an editable block may move; an uneditable block, an untagged event and a timed non-block event are fixed, and all-day events are ignored.
- 2026-11-11 `repack` places existing blocks first (by start time, ties by event id), then new tasks in the order given. Each item goes at the earliest spot after the one placed before it, so order is kept; an item with no room goes to `drops` and does not stop later, smaller items from using an earlier gap.
- 2026-11-11 A block that already ended before now is history: it is neither moved nor dropped. A block running right now is placed again from now with its full original length. The "running over" signal that fires when a block's end passes (the replan job) will not see an already-ended block through `repack`, so that job must handle it.
- 2026-11-11 Lengths round up to 5 minutes, so a block that is off the 5-minute grid (for example 9:00 to 9:32) shows up as a move even when nothing is in its way. The optional gap applies only between placed blocks, not after meetings, and rounds up to 5.
- 2026-11-11 Lengths are real elapsed minutes, so a clock-change day counts right. The repeated hour on the fall-back day cannot be told apart in 'HH:MM' strings (marked `// simple:` in the code).
