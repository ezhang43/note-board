- 2026-10-31 Divider fixes after the check of PR #226 (owner: "Fix after merge"; calls, recommended option). (1) The Divider button on an empty heading makes that line the divider: a heading with no words shows nothing, so it is an empty line, as SPEC says. An empty list item keeps its bullet and gets the divider after it (the earlier call): it shows a bullet, so it is not an empty line; SPEC now says so. (2) Right before a divider with no line above it, the Divider button adds no second divider; it puts the cursor on a new empty line below the divider. (3) Select All over a note that starts with a divider, then typing, gives a plain line: the first line's kind is kept as always, and a divider has no kind that words can take. (4) The cursor rule ("never on a divider") is in one place, the editor's selection watcher: a cursor on a divider moves beside it, to the end of the line above, or for a divider on the first line to the start of the line below. A cursor inside a divider took no typing in Chrome (reproduced after Ctrl+Z, and on a click). (5) Ctrl+A in a Journal note selects the whole note by hand: Chrome's own Select All selected nothing in a note that starts with a divider. (6) Backspace or Delete next to a divider takes one whole letter as the reader sees it (the browser's `Intl.Segmenter`), and does nothing where there is no letter on that side. (7) Left alone: a note that starts with a divider still has no way to type above it (Chrome never put the cursor there before either); Backspace at the start of the line below removes the divider, and Enter then Divider puts it back lower.
