- 2026-10-22 (owner picked option B, job 149, review 137-A H5): deleting an account first adds a marker to boards/{uid} (`deleting: 'started'`, the deleting page's `client`, `updatedAt`; the boards stay in it), and firestore.rules refuse board, version and shared-list saves under boards/{uid} while there is a marker; deletes still work. Order: mark, list the shares (after marking, so none can be added meanwhile), delete shares and records, replace the board by `{deleting: 'done', client, updatedAt}`, then version history and the list of shares, then the sign-in. My calls: while 'started', only the page that set it may change it; if a step before 'done' fails, that page takes the mark off (keeping the boards in it) without waiting, so its pages carry on and a shared board already gone is kept in Version history; that alone isn't "part-way". A 'started' marker over 10 minutes old (the page closed part-way) lets any page save again; pages wait 10½ minutes from when the server's copy of it arrived (not from its time, so a device clock that is off doesn't matter; a marker only in the offline copy never starts the wait), and a page opened on one left long ago still waits that long. 'done' comes before the version history goes, so a version another page saved just before is deleted too, and it stays online for good with nothing of the person's in it, so a device reopened later (even offline with saves waiting) can never put anything back; any page of theirs can run deleting again from 'done' (only the sign-in failed); it stays 'done' (the rules allow only 'done' over it). Other pages hold their changes ("Saving…") and show the boards in a 'started' marker; on 'done' they ask Google whether the sign-in is gone (a forced token refresh, again each minute up to 10 times) and sign out with the note only if it is, so another tab of the same browser never signs out the deleting tab, and a page whose deleting stopped at the sign-in can still try again. Known limit: after a failed delete, signing out by hand on such a page shows the "deleted" note. A page that saw the shared boards go while the account was marked removes them without a Version history copy (the rules refuse versions then); on the deleting page the mark is off first, so it keeps one. Pages from before this change take the marker for their boards gone and sign out at once. The Privacy policy and Delete your account page mention the marker.
