- 2026-10-23 (job 197, owner report "mobile bug with unload dishwasher"; recommended options, rule 4 exception). (1) **Holding the text being typed in** (the field that has the cursor) never lifts an item or picks up a card, on any touch screen, phone or tablet: the hold belongs to the phone's own cursor and selection. A swipe on it still moves the board, and a tap still narrows a bigger selection. Holding an item that isn't being typed in still lifts it (job 114). (2) **A lost finger ends its gesture as cancelled**, never as a drop: a waiting hold, an item lift or grip drag, a card drag and a resize each end the way a cancelled touch does, so nothing moves, when a new first finger touches the screen (or the same pointer comes down again), or when the page is hidden. Losing focus alone (an iframe, a system overlay) does not end them. A second finger does not either, so a pinch still works; if an iPhone ever counts the lost finger as still down, the next touch is a second finger and only hiding the page ends it (noted in the code as a known limit). One helper, `onLostFinger` in `touchHold.ts`, used by `holdOrPan`, `trackItemDrag`, `trackDrag` and `beginResize`. (3) **Low risk**: no saving, sync, undo or deleting code changes, and the stuck lift never removed the item from the board (it was hidden while lifted, and saved all along), so a reload already brought it back.
