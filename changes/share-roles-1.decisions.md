- 2026-10-22 Roles on shared boards (job 161, PR 1; owner: "roles all yes", D1-D6 as recommended). Calls made while building: "roles in use" means a comment or view key was ever made (the fields stay in `private/links`, empty when off), so turning all links off doesn't reopen joining the old way; the rules require the edit key to change at that moment (D1) and the shared board to hold no key from then on. A thread's resolved state is kept on its first comment, so the rules let an editor resolve any comment and a commenter only their own. Link keys must be 16 to 100 characters and different from each other. Removing someone must change every link that is on, the key still in a share from before included (enforced online). Lowering someone's role must change the keys of every role above their new one in the same step, since an editor has read them all (code review). A joins record can only be written together with the person's member record, so nobody can fill the storage with them. Deleting a shared board deletes its comments too. The link isn't shown as off until the private record has answered. The pretend server for tests and `npm run dev` gets roles in PR 2, when the app first uses them; PR 2's "remove" and "change role" must change the comment and view keys too.
