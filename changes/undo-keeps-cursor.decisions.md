- 2026-11-09 Undo or redo while typing in a checklist item (job undo-keeps-cursor, owner OK 2026-11-09; worker calls): the fix is in the one place every undo and redo of the open board goes through (Ctrl+Z / Ctrl+Y, the toolbar and phone buttons, the Undo message, the phone item bar), and acts only when the cursor was in a checklist item. While the item is still drawn (even moved by the undo, in its list or to another list), it is asked to take the cursor again, at the place in the text the cursor had, because the browser loses the cursor when React moves or redraws its row (code review). Else the cursor goes to the nearest item still drawn in the same list, above, else below; if none of the items it had is left but the list still draws items (its contents were replaced), the list's first item. When the list draws no item (the undo collapsed the card or its container), the whole selection is let go, not only that card, because any selected block with the cursor on the page is what Backspace deletes (code review); when the card itself is gone, the selection is as without typing. "Drawn" is one function (`drawnItems` in src/model/undoCursor.ts, built on `visibleItems`), so folded items (PR #239) hide their sub-items here too once `visibleItems` skips them. The phone item bar's Undo now uses the same code, so it no longer sends the cursor to an item hidden in a collapsed card. Left as is: `focusAfterRemoving` (the trash can's cursor rule) is not reused, since it doesn't know which rows are drawn after the change. Left for later (was so before this job): clicking the toolbar's Undo button while typing moves the keyboard to the button, so a Backspace after it can still delete a selected card.
